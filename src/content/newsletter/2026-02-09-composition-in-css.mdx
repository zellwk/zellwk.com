I got nothing depressing to share today, so guess that’s a victory of sorts? Hurray! 

Anyway, I’ve been thinking about CSS composition a lot since I began using Tailwind 2 years ago.  

I meant, Tailwind and other utility libraries kept harping on “composition” non-stop… so it sounded *reeeaally* important. 

But I’ve always thought their version of composition carried a heavy sense of naïveté, because to them, composition is just stacking CSS values onto an element… 

```html
<div class="p-4 border-2 border-blue-500"> ... </div>
```

That's nothing different from adding CSS values to a class!

```css
/* Thoo! */
.card {
  padding: 1rem; 
  border: 2px solid var(--color-blue-500)
}
```

This thought prompted me to dive deeper into the concept of composition. 

And I wrote an article about it. 

Here it is: [Composition in CSS](https://css-tricks.com/composition-in-css/). 

You might find it interesting since it’s such a foundational topic, yet few people touch on it. (Everyone assumes everyone else truly understands jargon, eh?)

## An exploration on base font-sizes

Speaking of CSS, I also wrote [an exploratory piece on base font size](https://css-tricks.com/we-might-need-something-between-root-and-relative-css-units-for-base-elements/), which is a unit between `em` and `rem`. It's called `bem`. (B for base). 

Now, don’t tell anyone this, but I find the `bem` unit kinda cute BEM has traditionally been the shorthand for [Block Element Modifier](https://zellwk.com/blog/css-architecture-1/) (a CSS naming technique) for a looonng time. (We won’t see BEM much nowadays, but it was almost like a golden rule back then). 

`bem` and BEM mean so different things that I can’t help but let out a little chuckle when I see `bem` 🤭. 

Well, I'd say feel free to [give this a read](https://css-tricks.com/we-might-need-something-between-root-and-relative-css-units-for-base-elements/) if you feel like diving into non-existent CSS properties for the heck of it.
