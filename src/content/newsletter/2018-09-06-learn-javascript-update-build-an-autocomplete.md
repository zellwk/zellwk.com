**What’s with the Todolist API?**

Ajax is confusing for many beginners. In this course, I want to make sure you understand basic Ajax thoroughly. That means you need to use it to build real components.

But we have a problem: Most open APIs (those that don’t need authentication through a server) lets you send only GET requests. That’s not good enough. You need to know how to send POST, PUT, and DELETE requests too.

That’s why I went ahead and created an API for you. You’ll be able to do GET, POST, PUT and DELETE requests for the Todolist. You’ll learn how to read the API and how to use the API in this update. Links up there! ☝️.

(Don’t worry if you have no idea what I’m talking about. When you get to Module 12 on Ajax, you’ll understand! :)).

**Diving into rabbit holes**

I got sidetracked when I tried to make lessons this week.

TWICE.

That’s why I ended up creating only four lessons. (I was aiming for seven).

I want to share where I got sidetracked because of two reasons:

1. You pre-ordered Learn JavaScript. You have a right to know.
2. Provide you with some encouragement if you got sidetracked as well.

Here’s what happened.

When I tried to make the Todolist API, I tried to make the backend for the API perfect. I always felt bad about the things I made because I wasn’t very good with MongoDB. So I dove deep into MongoDB this time. And I made my backend (almost) perfect! My code is super clean now :D (Yay)!

But of course, you’re not concerned about how I wrote my backend for the Todolist API. You’re concerned about how you’ll use it to build components. So this extra work I did isn’t important in the current context.

And this extra work took more than 1 day of my time! I could have produced so many more lessons! (_Proceeds to blame myself for not focusing on the important things_).

The worse part is, I did that not once, but twice.

When I tried to teach you how to use the Todolist API, I got distracted again. I wanted to show you how to make a perfect UX when Ajax is concerned. So I dove down another rabbit hole for implementing [Optimisitic UI](https://uxplanet.org/optimistic-1000-34d9eefe4c05).

Code for optimistic UI is pretty hard. If we were to go into Optimistic UI, we’ll spend many lessons understanding how it all works.

And that’s not the point for this course.

The point for this course is to teach you how to use JavaScript to build real components. I shouldn’t be teaching you how to make the perfect UX for every possible use case (and I’ve been trying to do so unknowingly!).

What’s important is for you to understand how to use JavaScript and be able to build components on your own. I’m not doing you a favor by adding complexity early in the process.

I’ve thought about it and I’m going to remove optimistic UI from the lessons.

On the same point: I realized I added a ton of complex info about Ajax in the advanced Ajax section. You won’t need them yet, and I’ll likely make you confused by telling you about them. I’m going to remove these lessons.

I’ll see if I can fit these lessons back in the course later, or maybe it’ll be better if I move them into a separate course.

When will I create this separate course?

It won’t be quick. I’ll have to complete Learn JavaScript first. That’s the priority. When that’s complete, I’ll tell you about my next project :)
